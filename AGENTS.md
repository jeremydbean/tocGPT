# Agent Notes and File Index

This file summarizes the repository layout and the purpose of key files so future edits can start here. Its scope is the entire repository.

## Top-level directories and scripts
- `src/`: C source for the MUD server. See [C source map](#c-source-map) below for per-file roles.
- `area/`: World definition files (`*.are`) for rooms, objects, mobiles, and resets.
- `player/`, `gods/`, `heroes/`, `corpse/`: Character and state data written by the game.
- `log/`: Runtime logs generated by the server.
- `backups/`: Saved data snapshots.
- `nicedb/`: Database artifacts for the game (see `src/nicedb.c` and the `nicedb` binary helpers).
- `startup.sh`, `toc_build.sh`, `docker-entrypoint.sh`, `Makefile`: Launch/build scripts for local runs and Docker builds.
- `install`, `cleanup`, `refresh`, `restartubuntu.bat`: Utility scripts for setup and maintenance.
- `README.md`: Basic setup guidance and Docker usage.

## World files (`area/`)
- `area/toc.are`: ToC-specific area definitions including greetings/ASCII art.
- `area/rom.are`: ROM area definitions and greeting text.
- Additional `*.are` files define other game zones; editing these changes world content (rooms, mobs, objects).

## Data directories
- `player/`: Individual player save files (plain text). Avoid committing sensitive data.
- `gods/`, `heroes/`: Special character tiers; structure mirrors `player/`.
- `backups/`: Manual or automated backups of player/state data.
- `log/`: Server logs; useful for debugging crashes or runtime issues.

## Build and runtime scripts
- `Makefile`: Builds the MUD binaries; target names match typical ROM/Envy codebases (e.g., `merc`).
- `toc_build.sh`: Helper to build the server binary and prepare assets.
- `startup.sh`, `docker-entrypoint.sh`: Start the server locally or inside Docker; set the port via `PORT`/`MUD_PORT`.
- `install`, `cleanup`, `refresh`: OS-level setup/maintenance helpers (permissions, dependencies, cleanup).
- `tests/parser_smoke.sh`, `tests/fuzz_parsers.sh`: Offline checks that boot areas and fuzz the area parser via `./merc --check-*` flags.

## C source map (`src/`)
- Core headers
  - `merc.h`: Primary header with game-wide types, macros, structs, externs.
  - `magic.h`, `maxload.h`, `db.h`: Supporting headers for spell metadata, object limits, and database loading helpers.
- Engine and networking
  - `comm.c`: Socket handling, game loop, descriptor management, I/O buffering.
  - `interp.c`: Command interpreter dispatch; ties player input to command functions.
  - `handler.c`: Core object/character manipulation helpers (affects, equipment, containers).
  - `db.c`: World loading (areas, resets, skills) and initialization sequences.
  - `save.c`: Persistence of player and object state to disk.
- `update.c`: Per-tick updates (regeneration, violence queue, weather); `update.c.bak` retains a backup.
- `maxload.c`: Tracks maximum loads of items/mobs; `maxload.h` declares interfaces.
- `nicedb.c`, `nicedb` (binary/helper scripts): Alternative database handling utilities.
- `comm.c`: Server entrypoint and socket setup; accepts `--check-areas`, `--check-area <file>`, and `--check-save <name>` for offline validation.
- Gameplay systems
  - `act_comm.c`: Communication commands (say, tell, channels, emotes).
  - `act_info.c`: Information commands (score, who, look, help).
  - `act_move.c`: Movement and room-entry logic.
  - `act_obj.c`: Object interactions (get, drop, wear, wield, containers).
  - `act_wiz.c`: Immortal/admin commands.
  - `fight.c`: Combat resolution, damage, combat round handling.
  - `magic.c`, `magic2.c`: Spell implementations and spell effect handlers.
  - `skills.c`: Skill handling and checks; often coordinates with `fight.c` and `magic*.c`.
  - `special.c`: Special procedures tied to mobiles/objects/rooms.
  - `quest.c`: Quest system definitions and commands.
  - `pkill.c`: Player-killing rules and enforcement.
  - `points`: Likely data/config for experience/skill point adjustments (text or binary depending on build).
- Utilities and extras
  - `wizlist.c`: Wizard list generation/utilities.
  - `misc.c`: Miscellaneous helpers not covered elsewhere.
  - `edit.c`: In-game editors for areas/objects/mobiles/help files.
  - `hunt.c`: Pathfinding/track routines (`hunt.c.bak` is a backup).
  - `imc.c.save`: Archived Intermud communication code.
  - `webserver.c.orig`, `webserver.c.disabled`: Experimental/disabled web server integration.
  - `const.c`: Static data tables (classes, races, skills, socials).
  - `interp`: Possibly a generated command table or supplemental interpreter resource.
  - `swe.txt`, `swedish.txt`, `swe.txt`: Language/localization samples.

## Notes for future changes
- Text banners and greetings live in `area/toc.are` and `area/rom.are`; keep ANSI codes consistent and reset colors to avoid bleed.
- Gameplay logic changes typically touch paired files: command declaration in `interp.c`/`interp.h`, implementation in `act_*.c` or related modules, and data tables in `const.c`.
- Saving/loading flows involve `save.c` and `db.c`; ensure structures in `merc.h` stay in sync.
- Network or timing behavior is centralized in `comm.c` and `update.c`.
